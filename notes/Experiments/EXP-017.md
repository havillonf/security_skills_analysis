# EXP-017 — Revisão de falsos positivos e refinamento do prompt

Experimento executado na branch `Q1-prompt-refinement`, ramificada de `Q1`.

## Objetivo

Avaliar se o [[Classification Prompt]] v2.6 produz falsos positivos nos casos de
consenso LLM que tiveram `confidence=low` em pelo menos um modelo, e propor
alterações ao prompt (v2.7) para reduzir esses falsos positivos sem quebrar a
confiabilidade já medida no [[EXP-014]].

## Motivação

Análise dos dados do [[EXP-014]] revelou que **51% dos SECONDARY aceitos por
consenso** (22/43) tiveram pelo menos um modelo marcando `confidence=low`. Isso
sinaliza que o prompt atual empurra os modelos a incluir casos marginais —
coerente com o `SECONDARY` deliberadamente inclusivo (R-2), mas potencialmente
inflando o numerador com casos que não deveriam ser Security Skill.

A pergunta que o EXP-017 responde: **desses casos marginais, quantos são
genuinamente borderline pelo Codebook v2.6 e quantos são falsos positivos causados
por ambiguidade no prompt?**

## Contexto no caminho crítico

Este experimento **precede o E-7** (validação do LLM local do orientador). Se o
prompt for revisado, o E-7 deve rodar com o prompt v2.7, não o v2.6. Ver
[[Decision Log#D-033]] e [[Decision Log#D-024]].

## Protocolo de revisão (Fase 2)

**Quem faz o quê:**
- **Havillon** lê todos os casos do subconjunto e preenche o CSV
- **Victor** é consultado apenas nos casos marcados `bring_to_victor = true`
- Casos confirmados por ambos como problemáticos são levados aos **orientadores**,
  com o `SKILL.md` original como exemplo concreto

**Para cada caso:**
1. Abrir `results/EXP-013_llm_cases/LLMxxx.md` (o `SKILL.md` original)
2. Ler sem ver os rótulos LLM primeiro
3. Avaliar contra o [[Codebook]] v2.6 e preencher no CSV:
   - `fp_assessment`: `correct` | `borderline` | `false_positive`
   - `fp_reason`: justificativa em texto livre (o que está errado/duvidoso no prompt)
   - `bring_to_victor`: `true` | `false`

> [!note] Sem κ nesta etapa
> O objetivo é diagnóstico do prompt, não medição de confiabilidade. Um único CSV,
> fluxo sequencial (Havillon → Victor nos selecionados). Ver [[Decision Log#D-033]].
