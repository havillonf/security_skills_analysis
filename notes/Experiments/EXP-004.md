# EXP-004 — Validação do detector de idioma

## Objetivo

Medir a confiabilidade do rótulo de idioma **antes** de usá-lo como variável de
estratificação do Desenho C ([[Decision Log#D-014]]).

Motivação: em [[EXP-003]] o `py3langid` reportou confiança média de 1,000 — valor
implausível que sugeria superconfiança.

## Método

Dois detectores **independentes** sobre a mesma amostra estratificada:

| | Detector |
|---|---|
| A | `py3langid` (fork de Lui & Baldwin 2012), `norm_probs=True`, limiar 0,90 |
| B | `lingua-language-detector`, *high accuracy mode* |

Prática adotada do **GitHub Multilingual Repositories Dataset**: manter a saída de
múltiplos classificadores em vez de colapsar num rótulo único.

Amostra: pool determinístico de 6.000 representantes
(`ORDER BY hash(file_sha)`), organizado em 7 estratos desenhados **para expor onde a
detecção falha** — não para representar a população. 18 por estrato, `seed = 20260822`.

```bash
uv run --with duckdb --with py3langid --with lingua-language-detector \
  python scripts/validate_language_detection.py --pool 6000 --per-stratum 18
```

> [!warning] Concordância não é acurácia
> Onde dois detectores concordam, ambos podem estar errados. Concordância é um
> **limite superior grosseiro** da confiabilidade. O que dá força ao resultado é a
> inspeção das discordâncias, não o número agregado.

## Artefatos

`scripts/validate_language_detection.py` ·
`results/EXP-004_langdetect_validation.json` · `results/EXP-004_disagreements.json`

## Observações

### 1. Concordância por estrato

| Estrato | n | Concordância |
|---|---|---|
| `S_en` | 18 | **1,000** |
| `S_latino` (de/es/pt/fr/it) | 18 | **1,000** |
| `S_cjk` (zh/ja/ko) | 10 | **1,000** |
| `S_muito_codigo` | 18 | 0,944 |
| `S_multilingue` | 18 | 0,944 |
| `S_texto_curto` | 18 | 0,889 |
| **`S_cauda`** (demais idiomas) | 18 | **0,667** |
| **Global** | **118** | **0,915** |

### 2. A confiança do `langid` não discrimina nada

Confiança do `py3langid` **nos casos em que ele discorda do lingua**:

| | valor |
|---|---|
| média | **0,969** |
| mínimo | 0,836 |
| máximo | **1,000** |

O detector reporta confiança de 1,000 enquanto erra. **A confiança do `langid` é
inútil como filtro neste corpus** — qualquer limiar sobre ela é arbitrário.

### 3. Inspeção das 10 discordâncias

| Padrão | n | Leitura |
|---|---|---|
| `la` → `en` | 4 | texto **claramente inglês**; langid errado |
| `km` → `en` | 1 | texto **claramente inglês** ("Post to X (Twitter)…"); langid errado |
| `vi` → `en` | 1 | inglês com fragmento vietnamita ("thiết kế / kiến trúc"); dominante é inglês |
| `ko` → `en` | 1 | **genuinamente misto** (estrutura inglesa, frases coreanas) |
| `ja` → `en` | 1 | **genuinamente misto** (japonês + inglês) |
| `und` → `la` | 1 | stub curto em inglês; **lingua** errado |
| `und` → `en` | 1 | trecho muito curto em inglês; langid conservador demais |

Placar: em **6 de 10** o langid erra e o lingua acerta; em **2** o rótulo correto é
`mixed` e nenhum dos dois o expressa; em **1** o lingua erra; em **1** o langid é
apenas conservador.

### 4. `la` é artefato, não idioma

Confirma a suspeita registrada em [[EXP-003]]: `la` (latim) é o rótulo que o langid
atribui a texto técnico em inglês. Quatro das dez discordâncias são desse tipo, e
todas com confiança 1,000.

## Interpretação

*(explicações possíveis, não conclusões)*

A detecção é **confiável exatamente onde há massa** (en, latinos, CJK: 100% de
concordância) e **não confiável na cauda** (66,7%). Isso é conveniente para o
Desenho C: os estratos que importam para a estimativa são justamente os estáveis.

O padrão dos erros é assimétrico e sistemático: o langid inventa idiomas raros
(`la`, `km`, `vi`) para texto **inglês**. Isso significa que a estimativa de não
inglês de [[EXP-003]] está provavelmente **superestimada**, não subestimada — a
direção do viés é conhecida.

Ordem de grandeza da correção: `la` (0,45%) + `vi` (0,25%) somam 0,70 pp. Se forem
majoritariamente inglês, o não inglês cai de 14,21% para perto de **13,5%**. É
ajuste pequeno, que não muda a conclusão de que a população é substancialmente
multilíngue.

Os dois casos `mixed` reforçam que o rótulo único é uma simplificação. A regra R-9
do [[Codebook]] já prevê `mixed`; falta operacionalizá-la.

## Conclusões

1. **`lingua` deve ser o detector primário**, com `py3langid` como segunda opinião.
   Onde discordam, o registro fica marcado — não se escolhe silenciosamente.
2. **Não usar a confiança do `langid` como filtro.** Média de 0,969 quando erra.
3. **A cauda não deve ser estratificada por idioma.** Colapsar em um único estrato
   `L5 = demais + und + mixed`; a detecção ali não sustenta separação.
4. Os estratos `en`, latinos e CJK são confiáveis o bastante para estratificação.
5. `la` deve ser tratado como **`und`/inglês provável**, nunca como idioma.

## Limitações

- **Não há ground truth humano.** Concordância entre dois detectores não é acurácia,
  e a inspeção das discordâncias foi feita por **LLM**, não por anotador humano
  ([[Decision Log#D-008]]). O resultado sustenta decisões de desenho; não é medida
  de acurácia publicável como tal.
- **n = 118**, estratificado para expor falhas. Não estima acurácia populacional.
- `S_cjk` teve apenas 10 casos no pool — suporte fraco para esse estrato.
- Os dois detectores compartilham limitações de família (ambos treinados sobre
  corpora gerais, não sobre texto técnico com código).
- Concordância pode ser inflada por erro correlacionado: onde ambos veem texto
  técnico inglês, ambos dizem `en` — o que pode estar certo, mas não foi verificado
  de forma independente.

## Próximos passos

1. Adotar `lingua` como primário e reprocessar a distribuição de [[EXP-003]],
   reportando os dois rótulos lado a lado.
2. Operacionalizar `mixed` para os 11,71% de conteúdo multi-script.
3. Se o piloto de anotação incluir verificação humana de idioma, aproveitar para
   produzir uma medida de acurácia de verdade.
